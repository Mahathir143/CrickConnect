2. Real-Time Cross-Device Communication Architecture

A primary architectural hurdle in sports overlays is ensuring that when a scorer taps a button on Mobile Phone 1, the stream overlay on Mobile Phone 2 or an OBS Studio PC updates in real time over any cellular carrier or Wi-Fi network.

Communication Model: Multi-tier hybrid synchronization combining MQTT over Secure WebSockets (WSS) for global cross-device push, with native BroadcastChannel and LocalStorage for same-machine zero-latency operations.

┌─────────────────────────────────┐
│     Mobile 1: Scorer Desk       │
│  (User taps 4 / 6 / OUT / Runs) │
└─────────────────────────────────┘
                 │
                 ▼
     [1. Local BroadcastChannel] ──> (Same-phone tabs update in 0ms)
                 │
                 ▼
     [2. MQTT over WSS Publish]
         Broker: wss://broker.emqx.io:8084/mqtt
         Topic:  crickconnect/v1/match/{matchId}
         Config: { qos: 1, retain: true }
                 │
      ┌──────────┴──────────┐
      ▼                     ▼
┌──────────────────┐  ┌──────────────────────────────┐
│ Mobile 2: Stream │  │ OBS Studio / Prism Live      │
│ Transparent View │  │ 1080p Browser Source Canvas  │
│ (< 80ms Latency) │  │ (< 80ms Latency)             │
└──────────────────┘  └──────────────────────────────┘

2.1 Why MQTT Retained Messages are Essential for Broadcast Overlays

Standard WebSockets only push messages to active listeners. If Mobile 2 opens the overlay 10 minutes into the match, a standard WebSocket would show a blank screen until the next ball is bowled. With retain: true in MQTT, the broker caches the latest match snapshot on the topic. The moment Mobile 2 or OBS connects, the broker pushes the current score in under 50ms!

3. Overlay Rendering Architecture: Exclusivity & Persistence Rules

The overlay adheres to two foundational broadcast production rules requested by professional commentators:

Rule 1: Bottom Scoreboard Persistence

• Controlled by overlayState.isBottomScorebarEnabled.
• If Enabled: The bottom scorebar remains visible at all times, even when popups, cards, or animations appear on screen.
• If Removed/Disabled: The bottom scoreboard is completely removed from the stream.

Rule 2: Popup Mutual Exclusivity

• Only ONE popup card (B1, B2, Bowler, Target, Partnership, FOW, Custom Banner, MOM) can be active at a time.
• Triggering a new popup immediately unmounts any previously visible popup.
• Clicking DEFAULT or STOP closes all open popups while retaining the bottom scoreboard.

4. Diagnostic Inspection Guide ("How to Find Issues")

When troubleshooting real-time connectivity or overlay rendering, follow this diagnostic checklist:

1 Verify Cloud MQTT WebSocket Connection

Open Chrome DevTools (F12) $\rightarrow$ select the Network tab $\rightarrow$ filter by WS (WebSockets). Verify that a persistent connection to wss://broker.emqx.io:8084/mqtt is established with status code 101 Switching Protocols.

2 Inspect Live Payload Frames

Click on the active WebSocket entry in the Network tab and open the Messages sub-tab. Whenever a ball is scored, you should see incoming and outgoing binary/text frames containing the JSON payload with snapshot and events.

3 Inspect OBS Studio CEF Browser Source

To inspect OBS Studio's internal browser source with Chrome DevTools:

# Start OBS Studio with remote debugging enabled
obs64.exe --remote-debugging-port=9222

# Open Google Chrome and navigate to:
http://localhost:9222
# Click on the CrickConnect browser source to open full DevTools inside OBS!

4 Check Browser Console for MQTT Dropouts

The application logs connection events. Look for [MQTT] Connected to EMQX!. If cellular carrier firewall blocks port 8084, verify that the automated fallback to wss://broker.hivemq.com:8884/mqtt is initiated.

5. Step-by-Step Issue Reproduction Procedures

Follow these standard test scripts to verify system resilience:

5.1 Reproducing Cross-Device Synchronization

  1. Open https://crickconnect.vercel.app/ on Phone 1 (cellular network).
  2. Open https://crickconnect.vercel.app/?mode=overlay on Phone 2 (different Wi-Fi network).
  3. On Phone 1, tap SIX (6).
  4. Expected Outcome: Within 100ms, Phone 2 updates the team score and triggers the center flame stinger animation.

5.2 Reproducing Offline Recovery & Reconnect Backoff

  1. In Chrome DevTools, open Network tab and set Throttling to Offline on Phone 1.
  2. Notice the status indicator changes from Live Synced to Local Only.
  3. Score 3 balls locally (events are queued in `localStorage`).
  4. Switch Throttling back to No throttling (Online).
  5. Expected Outcome: The MQTT client auto-reconnects within 3 seconds and flushes the latest snapshot to the broker, resyncing Phone 2.

5.3 Reproducing Bottom Scoreboard Persistence vs Popup Exclusivity

  1. Ensure bottom scoreboard is enabled (default).
  2. In the Score Controller, click B1. Striker card slides up; bottom scorebar remains visible.
  3. Click BOWLER. B1 card immediately hides; Bowler card displays; bottom scorebar remains visible.
  4. Click DEFAULT. Bowler card hides; only the bottom scorebar remains.
  5. Click Bottom Scoreboard: ENABLED (toggle to REMOVED). The bottom scorebar disappears completely.
